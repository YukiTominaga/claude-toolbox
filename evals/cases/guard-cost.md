## メモ

**この仕組みは API キー運用・CI 向けであり、サブスクリプションでは使わない。**
サブスクでは `total_cost_usd` はトークン数から計算した参考値にすぎず追加課金も発生しないので、
金額を上限にしても意味のある歯止めにならない。暴走の歯止めは `max_turns_per_run` が担う。
未設定なら実費では一切判定しない、という不活性の側もここで固定している。

`loop-run.sh` は `total_cost_usd` を常に台帳へ積む(止めるためではなく、
1 イテレーションの重さを測る相対指標として)。上限が設定されている場合にだけ、
ゲートがその日の合計で判定する。失敗した実行のコストも積む: 積まないと、
失敗を繰り返すループが無限に走れてしまう。

他の日のコストを合計しないことも確認している。
