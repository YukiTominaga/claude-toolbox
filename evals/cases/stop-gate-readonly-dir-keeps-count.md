## メモ

`stop-gate-no-state-dir` は**カウントファイルが存在しない**状態で `chmod 500` を再現する。
このケースはその隣、**カウントファイルが既にある**場合を見る。両者で挙動が分かれるのは、
以前の事前判定が既存ファイルへの追記オープン (`: >> "$STATE"`) だったためで、
追記に必要なのはファイルの w とディレクトリの x だけ、つまりディレクトリが読み取り専用でも
成功していた。一方 `>` での上書きもディレクトリの w を必要としないため、
「書けると判定 → 実際に書けてしまう」で辻褄が合っていた。

一時ファイル経由の置換にすると実経路がディレクトリへの新規作成を要求するので、
判定もそれに合わせる必要がある。合わせないと「書けると判定したのに書けない」となり、
カウントが増えないまま差し戻しだけを繰り返す(上限が数えられない)。

root で回すと `chmod` が効かず前提が崩れる。ガードに `: >> "$STATE"` を使えないのは
上記のとおりファイルが存在すれば成功してしまうためで、新規ファイルを作れるかで見ている。
