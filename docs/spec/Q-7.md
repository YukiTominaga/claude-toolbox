# goal.md の無いセッションで L1 の床を残す

用語: **L1** = `scripts/project-checks.sh` の実行。**赤** = exit 非 0、**緑** = exit 0。
**差し戻し** = フックが exit 2 で Claude の停止を止めること。
Q-9 は `docs/backlog.md` の項目(未着手)。

## 背景

`hooks/stop-gate.sh` は `stop_hook_active: true` を見ると無条件に `exit 0` する。
このフラグは、直前の停止がフックに差し戻された場合に true になる。

goal.md が無いセッション(= 内側ループが動いていない普通の作業セッション)では:

1. 1 回目の停止 → L1 が赤 → 差し戻し
2. Claude が修正して再度停止 → `stop_hook_active: true` → **検証せず素通し**

つまり **1 度差し戻されたら、以降 L1 が走らない**。修正が本当に赤を消したかを
誰も確かめないまま完了宣言できる。goal-gate はこのフラグを無視して毎ラウンド
判定するが、それは停止条件 4 層(ラウンド上限・予算・無進捗・done)を持つからで、
stop-gate は状態を持たないため「何回差し戻したか」を数えられないのが素通しの理由だった。

`stop_hook_active` が連鎖の終了後に false へ戻るかは環境依存とみなし、
**false を「リセットしてよい合図」としてのみ使う**(true が続く限りカウントを持ち越す)。
これなら false が二度と来なくても上限が効き、来ればそこで数え直される。

## 目的

goal.md の無いセッションでも、差し戻し後の再停止で L1 検証が走ること。
かつ、赤が直らない場合に無限に差し戻し続けないこと。

## 含まないもの

- goal.md を stop-gate が読むこと(2 つのフックが同じファイルを別々に解釈すると
  「どちらも検証しない」に倒れうる。読まない方針は維持する)
- 内側ループ中の L1 二重実行の解消(goal-gate と stop-gate が同一ターンで
  それぞれ検証することは許容する。コスト面の対策は Q-9 の担当)
- カウントファイルの TTL / GC
- 同一プロジェクトで並行する複数セッションの干渉(カウントはプロジェクト単位の
  ファイル 1 個とし、セッション ID では分けない)
- goal-gate 側の停止条件への変更
- `hooks.json` の設定変更

## 設計上の決定(実装が従うこと)

- カウントの保存先は `$CLAUDE_PROJECT_DIR/.claude/loop/stop-gate-pushback`(数値 1 行)
- **この状態ファイルが「変更なし」判定を汚してはならない**。stop-gate の変更判定は
  goal-gate と同じく pathspec `:(exclude).claude/loop` を付けて行う
  (`.gitignore` に頼らない。gitignore していないプロジェクトで静かに壊れるため)
- 差し戻しの上限は 3 回(定数。環境変数での上書きは設けない)
- 判定順序は上から: `cd` → git 管理下か → 変更があるか → L1 実行 → 赤なら上限判定

## 受け入れ条件

各条件に対応する eval ケースを併記する。新規ケースは `evals/bin/hook-cases.sh` に
シナリオを、`evals/cases/<id>.md` に `type: command` のケースを追加する。

- AC-1: `stop_hook_active: true` でも、変更があり L1 が赤なら `exit 2` で差し戻す
  (`stop-gate-active-red`)
- AC-2: 差し戻しは連鎖内で通算 3 回まで。4 回目の停止では L1 を**実行せず**
  (`calls_count` が増えない)`exit 0` で素通しし、stdout に文字列 `差し戻し上限` を
  含む `{"systemMessage":"..."}` を 1 行出す(`stop-gate-pushback-limit`)
- AC-3: `stop_hook_active: false` の停止ではカウントが 0 にリセットされ、
  その後あらためて 3 回差し戻せる(`stop-gate-pushback-reset`)
- AC-4: L1 が緑なら `exit 0` で通す。カウントは緑では減らさない
  (連鎖内で単調増加。赤緑の往復で上限に到達しなくなるのを防ぐ)(`stop-gate-green`)
- AC-5: 変更が無ければ検証しない。状態ファイルが未追跡で存在していても
  「変更あり」と誤判定しない(`stop-gate-clean`)
- AC-6: `.claude/loop` を作成・書き込みできない場合(eval では `chmod 500` で再現)、
  `stop_hook_active: true` なら従来どおり素通しし、`false` なら従来どおり検証する
  (`stop-gate-no-state-dir`)
- AC-7: 既存ケースが新しい挙動に更新されている(`stop-gate-active` は AC-1 の
  ケースに置き換える。`goal-l1-runs-in-pushback-round` と `inner-loop-l1` は
  往復ラウンドで stop-gate も L1 を実行することを期待値とする —
  `inner-loop-l1` の往復ラウンドは npm 呼び出しが 6 増える)
- AC-8: `CLAUDE_PROJECT_DIR=$(pwd) ./scripts/eval-run.sh` が exit 0(不合格 0 件。
  claude CLI 不在による rubric ケースの SKIP は許容する)
