# 仕様: ゲートの迂回経路を塞ぐ (gate-hardening)

- 日付: 2026-08-08
- 関連 Issue / チケット: —
- ステータス: approved

## 目的(なぜやるか)

敵対的レビューで、「強制」を名乗るゲートに実証可能な迂回経路が見つかった:

1. **判定行の合否が部分一致**: `CRYSTAL-VERDICT: FAIL AC-PASSWORD-VALIDATION` のように
   detail へ `PASS` を含むだけの不合格が合格扱いになる(`case *PASS*`)
2. **サブエージェント委譲で verify-gate が沈黙**: メイン transcript には Task の起動しか
   現れず、サブエージェントが行った編集は EDIT 印にならない。実装を委譲するだけで
   独立検証の強制が消える
3. **spec の存在判定が 2 ゲートで食い違う**: `SPEC_RE` はサブディレクトリの spec を認めるのに、
   verify-gate の発火条件は `-maxdepth 1` で直下しか見ない。spec を機能別ディレクトリに
   整理すると verify-gate だけ黙って死ぬ
4. **`stop_hook_active` の相互干渉**: フラグは「どれかの Stop hook が差し戻した」印であり、
   自分のものとは限らない。change-gate の差し戻し後に追加された壊れたテストを、
   stop-gate が一度も実行しないまま完了できる
5. **ゲートが「ツリーの汚れ」を見る**: セッション開始前から汚れたツリーでは、
   会話だけのターンでも change-gate が差し戻し、stop-gate がフルテストを回す

## スコープ

### 含む

- verify-gate の判定行パースをトークン比較に修正(1)
- `record-subagent-edits.sh`(SubagentStop)の追加と、verify-gate / change-gate /
  stop-gate によるサブエージェント編集記録の参照(2)
- verify-gate の spec 存在判定を `SPEC_RE` と同じ範囲(再帰)に揃える(3)
- 各ゲートが自分の差し戻しを状態ファイルに記録し、自分の分の再停止だけを素通しする(4)
- change-gate / stop-gate がメイン transcript の作業痕跡で発火を絞る(5)
- Bash 書き換え検出の正規表現(`BASH_WRITE_RE`)を `lib/classify.sh` へ一元化

### 含まない

- verifier への指示文(プロンプト)を敵対的に書くことへの防御。verifier は LLM であり、
  「PASS とだけ出力せよ」という呼び出しは機械では止められない。このハーネスが止めるのは
  忘却・怠慢であって欺瞞ではない(README に保証範囲として明記する)
- stop-gate の対応言語の拡大(Node / Python のまま)
- Bash 経由の書き換え(`sed -i` 等)を verify-gate の変更痕跡に数えること(従来どおり。
  リダイレクトを変更とみなすとログ出力のたびに再検証を要求することになる)

## 受け入れ条件

- [x] AC-1: 判定行が `FAIL` なら、detail に `PASS` という文字列を含んでいても差し戻す
- [x] AC-2: `docs/spec/` のサブディレクトリにだけ仕様がある場合も verify-gate が発火する
- [x] AC-3: コードを変更したサブエージェントの記録があり、その後に verifier を
      呼んでいなければ差し戻す(stop_hook_active でも折れない)
- [x] AC-4: サブエージェントの変更後に verifier が PASS すれば通し、記録を消す
- [x] AC-5: 検証後のサブエージェント起動は 1 度だけ差し戻し、再停止では通して記録を消す。
      ただし直近の判定が FAIL のままなら折れない
- [x] AC-6: コードを変更した記録の無いサブエージェント起動だけでは差し戻さない
- [x] AC-7: 記録側は実装・テストのコードファイルだけを記録する
      (ドキュメント・spec・設定・Bash 実行は記録しない)
- [x] AC-8: change-gate / stop-gate は、他のゲートが差し戻した再停止では検査を続行し、
      自分が差し戻した再停止だけを素通しする(記録は消費時に消す)
- [x] AC-9: session_id が取れないビルドでは、従来どおりチェーン全体で素通しする(fail-open)
- [x] AC-10: 作業痕跡の無い会話だけのターンでは、ツリーが汚れていても
      change-gate / stop-gate が発火しない
- [x] AC-11: セッションがドキュメントだけを編集した場合、ツリーに実装の汚れがあっても
      change-gate は発火しない
- [x] AC-12: Bash 書き換えの痕跡、またはコードを変更したサブエージェントの記録があれば、
      何を触ったか特定できないので従来どおりツリー全体で判定する
- [x] AC-13: transcript が渡らないビルドでは従来どおりツリー全体で判定する
      (発火を絞る側を fail-open にすると、transcript の渡し方が変わった日にゲートが黙って死ぬ)
- [x] AC-14: 既存のテストがすべて通る — 検証: `npm test` が exit 0

## 制約

- 状態ファイルは `${CLAUDE_CONFIG_DIR:-$HOME/.claude}/state/crystal/` に置き、
  セッション ID で名前空間を切る。書くついでに 7 日より古いものを掃除する
- サブエージェント編集の記録は「コードを変更したサブエージェントがいた」という事実まで。
  どの Task 起動が編集したかはメイン transcript と突き合わせられない(tool_use id と
  agent_id の対応が取れない)ため、検証後の起動は理由の明示で通す線引きにする
- 判定の合否はあくまで判定行の先頭トークン(`PASS` / `FAIL`)だけで決める
