# 仕様: 独立検証を強制する Stop hook (verify-gate)

- 日付: 2026-08-08
- 関連 Issue / チケット: —
- ステータス: approved

## 目的(なぜやるか)

crystal の目的 3「実装したセッションとは別の文脈で検証する」は、`crystal:verifier`
エージェントの定義があるだけで、呼ぶかどうかは散文任せだった。実際には
「日常の完了報告の前には使わない」と description に書かれており、目的として掲げながら
運用上は封印されている状態だった(goal-gate と stop-gate との三重実行を避けるため)。

goal-gate を削除したことで三重実行の理由は消えた。呼び出しの有無は
メインセッションの transcript から機械判定できるため、散文ではなく hook に移す。

## スコープ

### 含む

- `hooks/verify-gate.sh` の追加と Stop への登録
- 分類ロジックの共有ライブラリ化(`hooks/lib/classify.sh`)。`change-gate.sh` も
  そこを参照するように変更する
- `agents/verifier.md` の description を「変更したら必ず呼ぶ」に更新

### 含まない

- **別プロセス・別セッションでの検証**。サブエージェントは同一セッション・同一
  ワークツリーで動く。会話の経緯を引き継がない独立コンテキストという性質は満たすが、
  `claude -p` で本当に別セッションを起こすことはしない
- worktree による作業ツリーの隔離
- 受け入れ条件そのものの機械実行(AC に検証コマンドを併記して exit code で判定する方式)。
  判定は verifier の判断に委ね、ゲートはその結論だけを読む

## 受け入れ条件

- [x] AC-1: 実装コードを変更したまま verifier を呼ばずに応答を終えようとしたら
      exit 2 で差し戻す — 検証: `npm test` の `verify-gate.sh` スイートが exit 0
- [x] AC-2: 最後の変更より後に verifier を呼んでいれば素通しする
- [x] AC-3: 検証した後にコード(実装・テスト)を変更したら、再検証を要求する
- [x] AC-4: 検証後の `docs/spec/` 更新・設定ファイル更新では再検証を要求しない
      (仕様のステータス更新で抜けられなくなるのを防ぐ)
- [x] AC-5: サブエージェント起動ツールが `Agent` / `Task` のどちらの名前でも認識する
- [x] AC-6: `docs/spec/` に仕様が 1 つも無ければ発火しない
      (verifier が「検証不能」しか返せず、差し戻しても状況が変わらないため)
- [x] AC-7: 実装の変更が無い / このセッションが何も編集していない / transcript が無い /
      git 管理外 のいずれでも発火しない
- [x] AC-8: `CRYSTAL_VERIFY_GATE=off` で無効化できる
- [x] AC-9: JSONL に壊れた行が混ざっていても判定を続ける
- [x] AC-10: `change-gate.sh` の既存の振る舞いが共有ライブラリ化後も変わらない —
      検証: `npm test` が exit 0
- [x] AC-11: verifier が `CRYSTAL-VERDICT: FAIL` を返したら、未達の条件 ID を添えて
      差し戻す。`stop_hook_active` でも素通ししない
- [x] AC-12: 判定は判定行 1 行だけを根拠にする。本文の散文が紛らわしくても、
      判定行が `PASS` なら通す
- [x] AC-13: 判定行が読み取れない場合(古い verifier 定義 / `tool_result` 欠落)は
      1 度だけ差し戻し、再停止では素通しして詰ませない
- [x] AC-14: `hooks/verify-gate.sh` が読む番兵と `agents/verifier.md` が出力させる
      番兵が一致していることをテストが検査する

## 制約

- `stop_hook_active` では素通ししない。change-gate と違い「理由を述べれば省いてよい」
  余地がほとんど無く、verifier を呼べば自然に通るためループにならない
- 合否の判定材料は判定行 1 行に限る。自由記述の要約を読解する形にはしない
  (判定基準が曖昧になり、verifier の言い回し次第で結果が変わる)
- 判定行の契約は hook と `agents/verifier.md` の 2 箇所にまたがる。
  片側だけの変更でゲートが黙って無力化されないよう、両者の一致をテストで固定する
- 変更痕跡は編集ツール(Write / Edit / MultiEdit / NotebookEdit)だけを見る。
  Bash 経由の書き換え(`sed -i` 等)は取りこぼす。リダイレクトを変更とみなすと
  ログ出力のたびに再検証を要求することになり、誤検出の害の方が大きい
- 分類の正規表現を 2 つのゲートに書き写さない。定義は `hooks/lib/classify.sh` に 1 つ置く
- `stop-gate.sh` と verifier でテストが二重に走る。verifier が動くのは
  「実装を変更したまとまりごとに 1 回」なので許容する
