# 1 イテレーションで実行回数の予算を 2 回消費していた

loop-run.sh が loop-guard.sh を記録付きで呼び、その後に起動する /crystal:loop next の
手順 1 が同じゲートをまた記録付きで呼んでいた。start 行が 1 回の実行で 2 行積まれ、
max_runs_per_day が黙って半分になる。

loop-run.sh 側を --check に変えて修正済み。
「ゲート自身が記録する」設計は正しいが、**ゲートを二重に通す経路**を作ると壊れる。
新しい入口を足すときは、既存の入口と記録が重ならないかを確認すること。

## 経過 (2026-07-25)

loop-run.sh を --check に変更して解消。run-normal が start 行 1 行を固定している。
