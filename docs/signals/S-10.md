# 予算撤廃で loop-run.sh の多重起動を抑えるものが無くなる (flock が無い)

scripts/loop-run.sh に flock も PID ファイルも無い。max_runs_per_day: 8 は「1 日 8 回まで」として事実上の多重起動抑制も担っていたため、撤廃すると短周期 cron が複数プロセスを同時に走らせられる。

同時実行された複数プロセスは .claude/goal.md を共有する。hooks/goal-gate.sh:102-103 は round を、:183-206 は last_sig を read-modify-write するため、ラウンドを他プロセスに食われ、無進捗署名も競合する。max_rounds による停止が正しく数えられなくなる。

docs/spec/budget-removal.md では「含まないもの」として明示的に切った(撤廃と多重起動対策は別の問題であり、混ぜると仕様が 1 イテレーションに収まらなくなる)。

昇格させるなら「loop-run.sh に単一起動の保証を入れる」1 項目。無人実行を実際に cron に登録する前に必要。現在は無人実行を使っていないため急がない。

## 射程の追加 (2026-07-25 / Q-19)

同じ競合が `hooks/stop-gate.sh` の差し戻しカウントにもある。Q-19 は書き込みを原子的な置換に変えるが、それが塞ぐのは壊れた値を読むこと (torn read) だけで、`.claude/loop/stop-gate-pushback` を読んでから書くまでの間に他プロセスが書く競合 (lost update) は残る。上限 3 回が過小に数えられ、差し戻しが止まらなくなりうる。

**この競合は cron とは無関係に起きる**。同じプロジェクトで Claude Code のセッションを 2 つ開けば Stop hook は並行して走るため、上に書いた昇格条件 (無人実行の登録前) では永久に拾われない。条件を次に広げる: **無人実行を cron に登録する前、または同一プロジェクトで複数セッションを日常的に開くようになった時点の、いずれか早いほう**。

昇格させるときは 1 項目のまま扱ってよい。loop-run.sh の単一起動保証と `.claude/loop/` 配下の状態ファイルの排他は、同じ仕組み (ロックファイル) で解ける。
