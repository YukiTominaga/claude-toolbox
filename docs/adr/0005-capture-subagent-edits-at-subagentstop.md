# ADR-0005: サブエージェントの編集は SubagentStop の記録で捕捉する

- ステータス: accepted
- 日付: 2026-08-08
- 関連: docs/spec/gate-hardening.md, ADR-0002

## コンテキスト

verify-gate(ADR-0002)の判定材料はメインセッションの transcript だが、そこには
サブエージェントの起動(Task の tool_use)しか現れず、サブエージェントが中で
どのファイルを編集したかは載らない。このため、実装をサブエージェントに委譲する
だけで独立検証の強制が丸ごと沈黙していた(敵対的レビューで再現)。

制約として、どの Task 起動がコードを編集したかは特定できない
(メイン transcript の tool_use id と SubagentStop の agent_id の対応が取れない)。

## 決定

`record-subagent-edits.sh`(SubagentStop hook)が「コードを変更したサブエージェントが
いた」という事実だけを状態ファイル
(`~/.claude/state/crystal/<session_id>.subagent-code-edits`)に残し、
Stop 側のゲートがそれを読む。

- 記録があるとき、verify-gate はサブエージェント起動(AGENT 印)を
  「コードが変わったかもしれない」変更痕跡として扱う
- verifier の PASS を受理した時点で記録を消す
- 検証後の起動は、どれが編集したか特定できないため 1 度だけ差し戻し、
  「調査のみで変更なし」の明示で通す(ADR-0004 と同じ線引き)
- 記録が無ければ、起動だけでは差し戻さない(調査エージェントの誤検知を出さない)

## 検討した選択肢

### 案 A: SubagentStop で事実だけを記録し、印の順序で判定する(採用)

- 「いた/いなかった」の事実と、メイン transcript 上の印の並びだけから判定する。
  環境依存の照合を持ち込まない

### 案 B: transcript の timestamp と記録時刻の比較で順序を取る(却下)

- 却下理由: メイン transcript の timestamp 形式と `date` の出力形式の突き合わせが
  環境依存(BSD/GNU)になり、形式が変わった日に静かに壊れる

### 案 C: すべての Task 起動を無条件に変更痕跡とみなす(却下)

- 却下理由: 調査エージェントを走らせただけのターンが毎回差し戻される。
  verify-gate は stop_hook_active で折れない設計なので、抜けられないループになる

### 案 D: `claude -p` で検証を別プロセス化して委譲問題ごと消す(却下)

- 却下理由: ADR-0002 の案 B と同じ判断(コスト・認証環境依存・結果を会話へ戻す
  経路)で棄却済み

## 影響

### 得られるもの

- 実装をサブエージェントに委譲しても独立検証の強制が残る
- change-gate / stop-gate も同じ記録を使い、発火の要否を判断できる

### 受け入れるトレードオフ

- ゲート間でファイルベースの状態を共有する(セッション ID で名前空間を切り、
  7 日より古いものは書くついでに掃除する)
- 検証後の起動への差し戻しは理由の明示で通るため、そこは自己申告に委ねる

## 再検討の条件

- メイン transcript からサブエージェントの編集ファイルが直接引けるようになったとき
  (記録ファイル自体が不要になる)
