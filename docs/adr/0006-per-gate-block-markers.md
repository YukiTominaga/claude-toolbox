# ADR-0006: 差し戻しの自他は状態ファイルで区別する

- ステータス: accepted
- 日付: 2026-08-08
- 関連: docs/spec/gate-hardening.md, ADR-0004

## コンテキスト

Stop hook が受け取る `stop_hook_active` は「どれかの Stop hook が差し戻した」
フラグであり、自分が差し戻したかは分からない。crystal は Stop に 3 つのゲート
(change-gate / verify-gate / stop-gate)を登録しており、フラグだけで素通しすると
ゲート間で相互干渉が起きる。

具体的には: change-gate がテスト欠落で差し戻す → 壊れたテストが追加される →
再停止では `stop_hook_active=true` → stop-gate がテストを一度も実行しないまま
素通しする(敵対的レビューで指摘)。

一方で、素通しを全廃すると別の問題が出る。元から落ちているテストを直せない
プロジェクトでは、脱出口が無いとランタイムのブロック上限まで詰まる。

## 決定

change-gate / stop-gate は差し戻した事実を
`~/.claude/state/crystal/<session_id>.<gate>.blocked` に記録し、
`stop_hook_active` の再停止では「自分の記録があるときだけ」素通しする
(記録は消費時に消す)。他のゲートが差し戻したチェーンでは自分の検査を続行する。

session_id が取れないビルドでは従来挙動(フラグで素通し)に落とす。

## 検討した選択肢

### 案 A: ゲートごとの差し戻し記録で自他を区別する(採用)

- 「1 度だけ差し戻す」(ADR-0004)の脱出口を残したまま、他ゲートの差し戻しに
  よる検査の免除だけを塞ぐ

### 案 B: stop-gate も verify-gate と同様にフラグで折れない設計にする(却下)

- 却下理由: verify-gate は「verifier を呼べば必ず抜けられる」から折れない設計が
  成立する。stop-gate は元から落ちているテストを直せないプロジェクトで
  ランタイムのブロック上限まで詰まる。脱出口は残す必要がある

### 案 C: フラグでの素通しを全廃する(却下)

- 却下理由: session_id が取れないビルドで無限ループになる。
  session_id 不明時は従来挙動に落とすフォールバックが要る

## 影響

### 得られるもの

- 「どれかのゲートが差し戻すと他のゲートの検査が免除される」相互干渉が消える
- 各ゲートの「1 度だけ差し戻す」意味が、チェーン内の位置に依らなくなる

### 受け入れるトレードオフ

- ファイルベースの状態が増える(セッション ID で名前空間を切り、古いものは掃除する)
- 免除を述べて通った直後に別ゲートがチェーンを延ばすと、まれに同じ免除を
  もう一度述べる必要がある

## 再検討の条件

- Stop hook の入力に「どの hook が差し戻したか」が載るようになったとき
  (状態ファイルごと不要になる)
