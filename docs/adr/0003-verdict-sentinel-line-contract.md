# ADR-0003: verifier の合否は番兵 1 行の契約で読む

- ステータス: accepted
- 日付: 2026-08-08
- 関連: docs/spec/verify-gate.md, docs/spec/gate-hardening.md, ADR-0002

## コンテキスト

ADR-0002 の時点では、ゲートが担保するのは「独立検証を経たこと」までで、
verifier の判定内容(満たす/満たさない)は見ていなかった。理由は「verifier の
出力形式に hook が依存すると、書式を変えた瞬間に静かに壊れる」だったが、
このままでは verifier が「満たさない」と言っているのを無視して完了できてしまう。

「静かに壊れる」は、壊れ方を静かでなくすれば解決する問題だった。

## 決定

verifier は本文の末尾に判定行を 1 行返す契約とする:
`CRYSTAL-VERDICT: PASS` または `CRYSTAL-VERDICT: FAIL <未達の条件 ID>`。
`verify-gate.sh` は対応する `tool_result` からこの 1 行だけを読み、FAIL なら差し戻す。
合否は判定行の先頭トークンだけで決める(detail への部分一致は使わない)。

契約が hook と `agents/verifier.md` の 2 箇所にまたがるため、
`tests/verify-gate.test.ts` が両方のファイルを読んで番兵の一致を検査する。
書式を変えるとテストが落ちる(静かには壊れない)。

判定行が読み取れないときだけは 1 度で諦める。古い crystal がインストールされて
いると判定行が返らず、詰ませると `plugin update` すら打てなくなるため。

## 検討した選択肢

### 案 A: 番兵 1 行の契約 + 両側一致のテスト(採用)

- 判定基準が 1 行に固定され、散文の言い回しに左右されない。
  契約の破壊はテストで検出される

### 案 B: 判定サマリー(「満たさない: N件」)を正規表現で読む(却下)

- 却下理由: 自由記述の一部なので、verifier が言い回しを変えるたびに壊れる。
  本文に紛らわしい文字列があると誤判定もする(「満たさない: 0件 と書いてあるが
  紛らわしい文章」で回帰テストを置いた)

### 案 C: verifier に判定 JSON をファイルへ書かせる(却下)

- 却下理由: 書き忘れると差し戻しが続き、書き忘れを直す手段が verifier 側に
  しかないため抜けられなくなる

### 案 D: 受け入れ条件そのものを機械実行する(却下)

- 却下理由: AC に検証コマンドを併記して exit code で判定する方式は、削除した
  goal-gate の検証機構と同じものが戻る。判定は verifier に委ね、ゲートは
  その結論だけを読む形に留めた

### 案 E: 判定行が無い場合も詰むまで差し戻す(却下)

- 却下理由: 古い crystal がインストールされていると判定行が返らず、
  `claude plugin update` を打つ前に応答を終えられなくなる

## 影響

### 得られるもの

- 「検証は回したが不合格のまま完了」が機械的に止まる
- 判定基準が曖昧にならない(散文に「満たさない」とあっても判定行が PASS なら通す)

### 受け入れるトレードオフ

- verifier の出力形式への依存が生まれる。依存は消せないので、
  壊れたときにテストで気づける形にして受け入れる
- 判定行の欠落時は 1 度の差し戻しで通すため、その経路では合否の担保が無い

## 再検討の条件

- サブエージェントが構造化出力(スキーマ強制)を返せるようになったとき
  (番兵文字列より頑健な契約に置き換えられる)
