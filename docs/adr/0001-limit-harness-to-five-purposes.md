# ADR-0001: crystal のハーネスを 5 つの目的に絞る

- ステータス: accepted
- 日付: 2026-08-08
- 関連: docs/spec/change-gate.md

## コンテキスト

crystal には目的を定めないまま仕組みが増えていた。goal ループ一式(約 1,240 行)、
eval 一式(約 305 行)、`log-bash.sh`、`audit-config.sh`、`pre-bash-guard.sh`、
汎用論の rules 3 本。一方で spec 関連は 66 行、別文脈での検証は 38 行しか無く、
投資配分が目的に対して逆転していた。

さらに goal ループの存在が検証の仕組みを直接殺していた。`verifier` を日常フローで
呼ばない理由は「stop-gate / goal-gate と合わせてテストが三重に走るから」であり、
仕組み同士が互いの存在理由を打ち消し合っていた。

## 決定

crystal のハーネス部分が担う目的を次の 5 つに固定し、ここに当たらない仕組みは
置かない。goal ループ・eval・bash ログ・設定監査・破壊コマンドガード・目的外の
rules は削除する。

1. 決定の理由を ADR に残す
2. 実装と対になる spec が作られる
3. 実装とは別の文脈で検証する
4. 実装と対になるテストが必ず書かれる
5. 学びが次のセッションに残る

## 検討した選択肢

### 案 A: 5 つの目的に絞り、目的外を削除する(採用)

- 目的と投資配分を一致させる。goal-gate を外すことで、目的 3(verifier)を
  日常フローへ復帰させる制約も消える

### 案 B: goal ループを別 plugin に切り出す(却下)

- 却下理由: `/adr` と `/learn` が `goal-gate.jsonl` を情報源として参照していたため、
  分離しても依存が残り続ける。参照を切るなら削除と同じ作業量になるので、
  git 履歴に残すことで足りると判断した

### 案 C: eval を残して目的 4 に流用する(却下)

- 却下理由: eval は「再発防止の資産」で、「実装と対になるテストが書かれる」とは
  別物。プロジェクトのテストスイートでやるべきことを二重化するだけだった

### 案 D: `pre-bash-guard.sh` を settings.json の permissions へ移す(却下)

- 却下理由: 破壊コマンドの抑止自体が 5 目的のどれでもない。移設先を用意すると
  「移した先の保守」が plugin の責務として残るため、plugin からは落としきる方を採った

## 影響

### 得られるもの

- 仕組みを追加するときの判定基準(5 目的のどれに当たるか)ができる
- verifier を Stop hook で強制する道が開ける(→ ADR-0002)

### 受け入れるトレードオフ

- goal ループが持っていた「目標の宣言と達成確認」の機構は失われる。
  必要なら git 履歴から掘り起こす
- 破壊コマンドの抑止は plugin の外(各自の settings.json)の責任になる

## 再検討の条件

- 5 目的のいずれにも当たらないが、毎セッション手で繰り返している作業が
  新たに見つかったとき(目的の側を増やすかを検討する)
