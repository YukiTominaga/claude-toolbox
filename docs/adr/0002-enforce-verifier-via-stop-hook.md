# ADR-0002: 独立検証は verifier サブエージェントの呼び出し強制で実現する

- ステータス: accepted
- 日付: 2026-08-08
- 関連: docs/spec/verify-gate.md, ADR-0001, ADR-0003, ADR-0005

## コンテキスト

目的 3「実装とは別の文脈で検証する」は、`crystal:verifier` エージェントの定義が
あるだけで、呼ぶかどうかは散文任せだった。実際には verifier の description に
「日常の完了報告の前には使わない」と書かれており、目的として掲げながら運用上は
封印されていた(goal-gate・stop-gate との三重実行を避けるため)。

goal-gate の削除(ADR-0001)で三重実行の理由が消えた。「verifier を呼んだか」は
メインセッションの transcript から機械判定できる事実であり、rules/ の採用基準
(hook で強制できることは rules に書かない)に従えば hook に置くべきものだった。

## 決定

`verify-gate.sh`(Stop hook)がメインセッションの transcript を読み、
「最後のコード変更より後に `crystal:verifier` の呼び出しがあるか」を判定する。
無ければ exit 2 で差し戻す。判定は時系列に並ぶ印(EDIT / VERIFY)の最後を見る。

verifier はサブエージェントとして同一セッション・同一ワークツリーで動く。
得るのは「会話の経緯を引き継がない独立コンテキストが、仕様と実行結果だけで
判定する」という性質までとする。

## 検討した選択肢

### 案 A: Stop hook で verifier 呼び出しを強制する(採用)

- 呼び出しの有無は transcript から機械判定できる。呼べば印が VERIFY になって
  自然に通るため、差し戻しがループにならない

### 案 B: `claude -p` で本当に別セッションを起こす(却下)

- 却下理由: 目的 3 の文言(「別のセッション」)には最も忠実だが、削除したばかりの
  nested claude 構造が戻る。コスト・認証環境依存が大きく、判定結果を会話に戻す
  経路が stderr しか無い。サブエージェントでも「会話の経緯を引き継がない
  独立コンテキスト」という実質は得られる

### 案 C: worktree 隔離を必須にする(却下)

- 却下理由: 実装が汚したツリーではなくクリーンな状態で検証できるが、
  ビルドキャッシュが効かず検証が遅くなる。まずは文脈の隔離だけを取る

### 案 D: 「一度でも verifier を呼んだか」で判定する(却下)

- 却下理由: 指摘を直した後の状態が検証されないまま完了できてしまう。
  最後の変更との前後関係を見る形にした

## 影響

### 得られるもの

- 「実装した文脈のまま自己申告で終える」ことが機械的に止まる
- verifier の呼び出しが習慣ではなく契約になる

### 受け入れるトレードオフ

- 実装が汚したツリーを見る点は残る(worktree 隔離はしていない)
- `stop-gate.sh` と verifier でテストが二重に走る。verifier が動くのは
  「実装を変更したまとまりごとに 1 回」なので許容する
- verifier への指示文はメインエージェントが書くため、欺瞞(PASS とだけ出力させる等)は
  止められない。このゲートが止めるのは忘却・怠慢まで

## 再検討の条件

- サブエージェントの実行環境が worktree 隔離を既定で安価に提供するようになったとき(案 C の再評価)
- 判定結果を構造化して親へ返す公式の経路ができたとき(案 B の再評価)
