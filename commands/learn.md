# /learn — セッション振り返りと知見の抽出

このセッションでの作業を振り返り、将来のセッションで再利用できる知見を抽出して永続化してください。

## 手順

### 1. セッションを振り返る

ここまでの会話を振り返り、以下に該当するものを洗い出す:

- **ハマりポイント**: エラーや想定外の挙動に遭遇し、解決に複数回の試行を要したもの
- **非自明な発見**: ドキュメントに書かれていない仕様・コードの隠れた結合・環境の罠
- **確立した手順**: 今後も繰り返し使えるコマンド列・ワークフロー・デバッグ手法
- **ユーザーからの修正・フィードバック**: 指摘されて直したこと（同じ指摘を二度受けないために）

該当がなければ「特筆すべき知見なし」と正直に報告して終了する。無理に絞り出さない。

### 2. 保存先を知見の性質で振り分ける

| 知見の性質 | 保存先 |
|---|---|
| このプロジェクト固有（チームでも有用） | プロジェクトの `.claude/learnings.md` に追記 |
| 個人的・プロジェクト横断の好みや事実 | ビルトインのメモリディレクトリ（MEMORY.md 経由） |
| 汎用的な技術手順で、トリガー条件が明確に書ける | `~/.claude/skills/<name>/SKILL.md` として新規スキル化を**提案**（作成前にユーザーへ内容を確認） |
| 再発している問題・二度と壊したくない挙動 | `evals/cases/` に eval ケースとして追加を**提案**（`/crystal:eval add` と同形式） |

`.claude/learnings.md` は SessionStart hook（`session-learnings.sh`）が次回以降の
セッション開始時にコンテキストへ自動注入する。つまりここに書いたものは実際に読まれる。
末尾 8000 バイトまでが対象なので、1エントリを短く保つこと。

### 2.5. 再発問題の eval ケース化

抽出した問題が次のいずれかで **2回以上** 現れている場合、eval ケース化を提案する:

- プロジェクトの `.claude/learnings.md` の既存エントリ
- `~/.claude/logs/goal-gate.jsonl` の差し戻し履歴（同種の未達理由の繰り返し）
- 今回のセッション内（同じ失敗を複数回修正した等）

提案時は id / type (command 優先、主観評価のみ rubric) / run（または rubric の観点）の案を
示し、ユーザー承認後に `evals/cases/<id>.md` を作成する。形式は templates/eval-case.md に従う。

### 3. learnings.md への追記フォーマット

```markdown
## YYYY-MM-DD: <一行タイトル>
<2〜5行: 何が起きたか、解決策/知見、なぜ重要か>
```

### 4. 結果を報告する

抽出した知見の一覧と、それぞれの保存先を簡潔に報告する。
スキル化の提案がある場合は、name / description / トリガー条件の案を示して承認を求める。

## 注意

- リポジトリが既に文書化している内容（README、CLAUDE.md、コメント）は重複保存しない
- 機密情報（トークン、認証情報、内部URL）を知見に含めない
- 1回の /learn で保存するのは本当に価値のある数件に絞る（量より質）
